## 1. 모델 학습과 성능 평가란?

### 1.1 모델 학습 (Model Training)

모델 학습은 **주어진 데이터를 바탕으로 모델의 내부 파라미터를 조정하여 예측 오차 또는 목적 함수를 개선하는 과정**이다.

- **입력(Feature, X):** 모델에 제공하는 정보. 예: 사용자가 평가한 영화, 영화 장르, 영화 태그.
- **정답(Target/Label, y):** 학습 또는 평가의 기준. 예: 사용자가 실제로 남긴 평점.
- **파라미터(Parameter):** 학습을 통해 결정되는 값. 예: 행렬분해에서 사용자·영화 잠재벡터.
- **하이퍼파라미터(Hyperparameter):** 학습 전에 정하거나 검증 데이터로 선택하는 설정. 예: 학습률, 잠재요인 수, 정규화 강도, 군집 수 K.
- **손실 함수(Loss Function):** 예측과 정답이 얼마나 다른지 수치로 계산하는 함수.

모든 모델이 경사하강법을 사용하는 것은 아니다. 예를 들어 인기 기반 추천은 평점 빈도를 집계하고, 콘텐츠 기반 추천은 텍스트 벡터와 유사도를 계산하며, K-Means는 군집 중심을 반복 갱신한다. 이 역시 넓은 의미에서 데이터를 활용해 모델을 구성하거나 적합하는 과정이다.

### 1.2 성능 평가 (Model Evaluation)

성능 평가는 **학습에 사용하지 않은 데이터 또는 별도로 정의한 평가 기준으로 모델의 성능과 일반화 능력을 측정하는 과정**이다.

평가해야 하는 이유는 다음과 같다.

1. 학습 데이터에서만 좋은 모델인지, 새로운 데이터에서도 작동하는지 확인한다.
2. 여러 알고리즘을 같은 조건에서 비교한다.
3. 과적합·과소적합을 진단한다.
4. 개선 방향을 실험 결과에 근거하여 선택한다.
5. 서비스 목적에 맞는 성능인지 판단한다.

**핵심:** 학습에서의 목표는 손실을 줄이는 것이지만, 프로젝트에서의 최종 목표는 **새로운 상황에서 실제로 유용한 결과를 내는 것**이다.

## 2. 모델 학습의 기본 원리

### 2.1 손실 함수 (Loss Function)

모델의 예측값을 `ŷ`, 실제값을 `y`라고 할 때, 손실 함수는 두 값의 차이를 수치화한다.

대표적인 회귀 손실 함수:

**평균제곱오차(MSE)**

$$\mathrm{MSE}=\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat y_i)^2$$

오차를 제곱하므로 큰 오차에 더 큰 페널티를 부과한다.

**평균절대오차(MAE)**

$$\mathrm{MAE}=\frac{1}{n}\sum_{i=1}^{n}|y_i-\hat y_i|$$

오차의 절댓값을 평균하므로 평점 단위로 직관적으로 해석할 수 있다.

분류 모델에서는 일반적으로 **교차 엔트로피 손실(Cross-Entropy Loss)** 등을 사용한다. 추천 시스템에서도 모델에 따라 평점 예측 오차, 순위 관련 손실, 사용자-아이템 상호작용에 대한 목적 함수 등을 사용한다.

### 2.2 최적화와 경사하강법 (Gradient Descent)

파라미터를 `θ`, 손실 함수를 `L(θ)`, 학습률을 `η`라고 할 때:

$$\theta_{t+1}=\theta_t-\eta\nabla_\theta L(\theta_t)$$

- **기울기(Gradient):** 손실이 증가하는 방향과 크기를 나타낸다.
- **학습률(Learning Rate):** 한 번에 파라미터를 얼마나 변경할지 결정한다.
- **Epoch:** 전체 학습 데이터를 한 번 사용하는 학습 주기.
- **Batch:** 파라미터를 한 번 갱신할 때 사용하는 데이터 묶음.

학습률이 너무 크면 최솟값 부근에서 진동하거나 발산할 수 있고, 너무 작으면 수렴이 느릴 수 있다.

### 2.3 정규화 (Regularization)

학습 데이터의 잡음까지 과도하게 학습하지 않도록 모델 복잡도를 제어한다.

예를 들어 L2 정규화가 적용된 목적 함수는 다음과 같이 쓸 수 있다.

$$L_{total}=L_{data}+\lambda\lVert\theta\rVert_2^2$$

여기서 `λ`는 정규화 강도다. 지나치게 큰 값은 학습을 과도하게 제한해 과소적합을 일으킬 수도 있다.

추천 시스템의 행렬분해에서도 잠재벡터에 정규화를 적용해 관측된 평점에만 과도하게 맞추는 현상을 완화할 수 있다.

## 3. 데이터 분할: Train / Validation / Test

| 구분 | 역할 | 사용 원칙 |
|---|---|---|
| **Train (학습)** | 파라미터 학습 | 모델이 학습하는 데이터 |
| **Validation (검증)** | 모델·하이퍼파라미터 선택 | 실험·튜닝에 반복 활용할 수 있음 |
| **Test (시험)** | 최종 일반화 성능 추정 | 모델 선택이 끝난 후 평가하는 것이 원칙 |

예를 들어 데이터를 **학습 70% / 검증 15% / 시험 15%**로 나눌 수 있다. 이는 예시 비율이지 반드시 지켜야 하는 고정 규칙은 아니다.

### 3.1 왜 데이터를 나눌까?

학습에 사용한 데이터를 그대로 평가하면 모델이 해당 데이터를 **외웠을 뿐인데도 성능이 높게 측정될 수 있다.** 실제 목표는 학습 과정에서 보지 못한 사례에 대한 성능이기 때문에 독립적인 평가가 필요하다.

### 3.2 교차 검증 (Cross-Validation)

**K-Fold 교차 검증**은 데이터를 K개 부분으로 나누고, 각 부분을 번갈아 검증 집합으로 사용해 평균 성능을 계산하는 방법이다.

예: 5-Fold라면 5차례 학습·검증을 반복한다. 이때 최종 시험 집합은 별도로 보관할 수 있다.

- 장점: 단일 분할에 따른 우연을 줄이고 성능 변동성을 확인할 수 있다.
- 단점: 학습 반복으로 계산 비용이 증가한다.
- 주의: 시계열 데이터나 사용자별 의존성이 있는 데이터는 무조건 임의 K-Fold를 적용하면 안 된다.

### 3.3 추천 시스템의 세 가지 데이터 분할

영화 추천에서는 무엇을 20%로 나누는지에 따라 평가 목적이 완전히 달라진다.

**① 상호작용(평점 기록) 단위 분할**

- 동일 사용자의 평점 기록 중 일부를 학습에서 숨기고 예측한다.
- 예: 한 사용자의 20개 평점 중 16개는 학습, 4개는 시험.
- 목적: **기존 사용자의 보지 않은 영화에 대한 예측** (Warm Start).

**② 사용자 단위 분할**

- 사용자 자체를 학습 집합과 시험 집합으로 분리한다.
- 예: 전체 사용자 중 80%는 학습에, 20%는 시험에 배정.
- 목적: **학습에 없던 신규 사용자에 대한 일반화 또는 콜드스타트**를 평가할 수 있다.
- 주의: 사용자 잠재벡터를 학습하는 일반적 협업 필터링은 신규 사용자에 대한 추가 입력·적응 과정 없이 예측하기 어려울 수 있다. 모델이 신규 사용자의 일부 평점을 입력받도록 설계했는지도 함께 명시해야 한다.

**③ 시간 순서 분할**

- 과거 상호작용으로 학습하고 미래 상호작용을 예측한다.
- 예: 사용자의 마지막 평가 영화 1편을 시험 데이터로 보관.
- 목적: 실제 서비스에서 미래 행동을 예측하는 상황에 더 가깝게 평가한다.

**중요:** “사용자 20%를 시험에 사용했다”와 “각 사용자의 평점 20%를 시험에 사용했다”는 **동일한 말이 아니다.** 프로젝트 보고서에는 분할 단위와 기준을 정확하게 적어야 한다.

## 4. 일반화, 과적합, 과소적합

### 4.1 일반화 (Generalization)

학습에 사용하지 않은 새로운 데이터에서도 일정한 성능을 유지하는 능력이다. 머신러닝에서는 학습 데이터의 점수 자체보다 일반화 성능이 중요하다.

### 4.2 과적합 (Overfitting)

- 학습 성능은 매우 좋지만 검증·시험 성능이 나쁜 상태.
- 원인 예: 모델 복잡도 과다, 데이터 양 부족, 잡음 학습, 지나친 튜닝.
- 대응: 정규화, 모델 단순화, 더 많은 적절한 학습 데이터, 조기 종료(Early Stopping), 검증 절차 개선.

### 4.3 과소적합 (Underfitting)

- 학습 데이터와 검증 데이터 모두 성능이 낮은 상태.
- 원인 예: 모델 표현력 부족, 중요한 특성 누락, 학습 불충분, 정규화 과도.
- 대응: 특성 개선, 모델 표현력 확대, 학습 조건 조정.

### 4.4 학습 곡선 (Learning Curve)

학습 횟수(Epoch)별 Train Loss와 Validation Loss의 변화를 비교한다.

- 두 손실이 함께 감소: 학습이 진행 중일 가능성.
- 학습 손실만 계속 감소하고 검증 손실은 증가: 과적합 가능성.
- 두 손실이 높은 수준에서 정체: 과소적합 또는 최적화 실패 가능성.

**조기 종료(Early Stopping)**는 검증 성능이 일정 기간 개선되지 않으면 학습을 멈추는 방법이다. 단, 모든 추천 모델이 Epoch 기반 학습을 수행하는 것은 아니다.

### 4.5 데이터 누수 (Data Leakage)

데이터 누수는 **실제 예측 시점에는 알 수 없는 정보가 학습 또는 모델 선택 과정에 들어가 성능이 비정상적으로 높아지는 문제**다.

주요 사례:

- 전체 데이터로 정규화 평균·표준편차를 구한 뒤에 Train/Test로 나누는 경우.
- Test에서 숨겨야 할 평점이 사용자 평균, 영화 평균, 유사도 또는 잠재벡터 계산에 이미 들어간 경우.
- 시험 결과를 보며 하이퍼파라미터를 여러 번 수정하는 경우.
- 미래 평점을 예측하면서 미래의 상호작용으로 사용자 프로필을 만든 경우.

**안전한 원칙:** 평가 목표를 먼저 정하고 데이터를 분할한 뒤, 감독학습에 필요한 통계량·사용자 프로필·상호작용 기반 유사도·모델 파라미터는 학습 데이터만으로 추정한다. 검증 데이터로 모델을 선택하고, 시험 데이터는 최종 비교에 사용한다.

단, 영화 제목·장르처럼 실제 추천 시점에 이미 공개되어 있는 **아이템 메타데이터**는 숨겨야 하는 정답 평점과 성격이 다르다. 사용 가능 범위는 평가 시나리오에 따라 정의한다.

## 5. 지도학습 모델 평가: 회귀와 분류

### 5.1 회귀 (Regression)

평점처럼 연속적인 수치를 예측할 때 사용한다.

| 지표 | 의미 | 방향 |
|---|---|---|
| MAE | 예측값과 실제값의 절대 오차 평균 | 낮을수록 좋음 |
| MSE | 예측 오차 제곱의 평균 | 낮을수록 좋음 |
| RMSE | MSE의 제곱근 | 낮을수록 좋음 |
| R² | 기준 예측 대비 설명력 | 높을수록 대체로 좋음 |

**RMSE (Root Mean Squared Error)**

$$\mathrm{RMSE}=\sqrt{\frac{1}{n}\sum_{i=1}^n(y_i-\hat y_i)^2}$$

예: 실제 영화 평점이 4.0점인데 3.2점으로 예측했다면 절대오차는 0.8점이다. 여러 평점에 대해 오차를 모아 MAE·RMSE를 계산한다.

**주의:** RMSE가 낮다고 해서 반드시 사용자에게 더 만족스러운 추천 순위를 만들어 준다는 뜻은 아니다. 평점 **예측 정확도**와 추천 **순위 품질**은 다른 목표다.

### 5.2 분류 (Classification)

예: 영화에 4점 이상을 준 경우를 '선호', 미만을 '비선호'로 **임의 정의**하여 분류하는 문제.

| 지표 | 계산 또는 의미 | 주의점 |
|---|---|---|
| Accuracy | `(TP + TN) / 전체` | 클래스 불균형에서 왜곡 가능 |
| Precision | `TP / (TP + FP)` | 선호한다고 예측한 것의 정확도 |
| Recall | `TP / (TP + FN)` | 실제 선호 항목을 찾은 비율 |
| F1-score | `2PR / (P + R)` | 정밀도와 재현율의 조화평균 |
| ROC-AUC | 임계값에 따른 TPR·FPR 구분 능력 | 불균형 데이터에서 PR-AUC도 검토 |

여기서 TP는 True Positive, FP는 False Positive, FN은 False Negative, TN은 True Negative다. 분모가 0인 경우에 대한 처리 규칙도 명시해야 한다.

**예시:** 실제 선호 영화 10편 중 8편을 찾아내면 Recall = 8/10 = 0.8이다. 하지만 추천한 전체 영화가 몇 편인지 알 수 없으므로 이 정보만으로 Precision은 계산할 수 없다.

## 6. 비지도학습 모델 평가: 군집화

5주차 고객 군집화 실습과 연결되는 평가 방식이다. 군집화에는 정답 라벨이 없는 경우가 많으므로 군집 내부 구조를 평가하는 지표를 사용한다.

### 6.1 실루엣 계수 (Silhouette Score)

$$s(i)=\frac{b(i)-a(i)}{\max(a(i),b(i))}$$

- `a(i)`: 같은 군집 내 다른 점들과의 평균 거리.
- `b(i)`: 가장 가까운 다른 군집과의 평균 거리.
- 값의 범위: **-1 ~ 1**, 높을수록 일반적으로 군집 간 분리가 뚜렷하다.
- 0에 가까우면 군집이 겹칠 가능성, 음수이면 다른 군집에 더 가까울 가능성을 시사한다.

### 6.2 다른 군집화 지표

- **Inertia / WCSS:** K-Means에서 군집 내 제곱거리 합. 작을수록 데이터가 중심에 가까우나 K가 늘면 보통 감소하므로 단독 비교에 부적절하다.
- **Davies–Bouldin Index:** 군집 내 퍼짐과 군집 간 분리를 함께 비교. 낮을수록 좋다.
- **Calinski–Harabasz Index:** 군집 간 분산 대비 군집 내 분산. 높을수록 좋다.
- **ARI (Adjusted Rand Index):** 비교할 **정답 라벨 또는 참조 군집**이 있을 때 군집 일치도를 평가한다. 라벨이 없다면 일반적 의미의 정답 정확도로 사용할 수 없다.

**해석 시 주의:** 실루엣 점수가 높더라도 실제 소비자 세그먼트의 사업적 의미, 군집 규모의 균형, 결과의 안정성까지 자동으로 보장하지는 않는다.

## 7. 추천 시스템에서의 성능 평가

MovieRecLab에 직접 연결되는 핵심 부분이다.

### 7.1 평가의 두 가지 목표

**① 평점 예측 (Rating Prediction)**

- 질문: “이 사용자가 영화 A에 몇 점을 줄까?”
- 정답: 시험 데이터에 숨겨 둔 실제 사용자 평점.
- 지표: **MAE, RMSE**.
- 비교 대상 예: 전체 평균, 사용자 평균, 아이템 평균, 편향 보정 모델, 잠재요인 모델.

**② Top-K 추천 순위 (Top-K Ranking)**

- 질문: “추천 목록 상위 10편에 실제로 사용자가 좋아하는 영화가 얼마나 들어가고, 앞쪽에 배치되는가?”
- 정답: 시험 구간에서 관측된 선호 영화 또는 별도로 정의한 관련성 점수.
- 지표: **Precision@K, Recall@K, Hit Rate@K, NDCG@K, MAP@K**.

두 목적의 지표는 직접적인 우열 관계가 없다. 실제 시연 서비스가 영화 목록을 추천하는 것이라면, 평점 예측 지표 외에 **순위 평가를 반드시 병행하는 것이 바람직하다.**

### 7.2 Precision@K

상위 K개 추천 영화 중 실제 선호 영화가 차지하는 비율이다.

$$\mathrm{Precision@K}=\frac{|\mathrm{TopK}\cap\mathrm{Relevant}|}{K}$$

예: 상위 5편 중 실제 선호 영화가 3편 → **Precision@5 = 3/5 = 0.60**.

### 7.3 Recall@K

시험 데이터의 실제 선호 영화 중 추천 목록에 포함된 비율이다.

$$\mathrm{Recall@K}=\frac{|\mathrm{TopK}\cap\mathrm{Relevant}|}{|\mathrm{Relevant}|}$$

예: 실제 선호 영화 4편 중 상위 5개에 3편 포함 → **Recall@5 = 3/4 = 0.75**.

### 7.4 Hit Rate@K

사용자별 Top-K 목록에 실제 선호 영화가 **하나라도 포함되면 1**, 없으면 0으로 처리한 뒤 사용자 평균을 구한다.

예: 10명 중 7명에게 적어도 한 편의 관련 영화를 추천 → **Hit Rate@5 = 0.70**.

### 7.5 NDCG@K (Normalized Discounted Cumulative Gain)

관련성 높은 영화를 **추천 순위의 앞쪽에 배치할수록** 높은 점수를 부여한다. 순위가 뒤로 갈수록 기여를 할인한다.

이진 관련성(0/1)을 사용하는 한 가지 정의:

$$\mathrm{DCG@K}=\sum_{i=1}^{K}\frac{rel_i}{\log_2(i+1)}$$

$$\mathrm{NDCG@K}=\frac{\mathrm{DCG@K}}{\mathrm{IDCG@K}}$$

- `rel_i`: i번째 추천 영화의 관련성.
- `IDCG`: 같은 평가 대상에서 얻을 수 있는 이상적인 DCG.
- 1에 가까울수록 이상적인 순위에 가깝다(비음수 관련성 기준).

예를 들어 똑같이 3편을 맞혔더라도 **1·2·3위에 맞힌 모델**이 **3·4·5위에 맞힌 모델**보다 NDCG가 높다.

### 7.6 추천 평가에서 특히 조심할 점

1. **관련성 기준:** 예를 들어 실제 평점 4.0점 이상을 '선호'로 정의할 수 있지만, 이는 프로젝트에서 명시적으로 선택하는 기준일 뿐 절대적인 정답이 아니다.
2. **관측되지 않은 영화:** 사용자가 평가하지 않았다는 이유만으로 **싫어하는 영화라고 단정하면 안 된다.** 평점 미관측은 부정적 반응의 증거가 아니다.
3. **후보군 (Candidate Set):** 모든 영화 중에서 추천할지, 평가 가능한 시험 영화만 후보로 둘지에 따라 지표 값이 크게 달라진다. 모델마다 동일한 후보군을 사용해야 한다.
4. **이미 평가한 영화 제외:** 신규 추천 실험에서는 학습에 사용한 기평가 영화를 후보 목록에서 제외할지 명시한다.
5. **사용자별 평균:** 다수 평점을 남긴 사용자가 지나치게 큰 영향을 주지 않도록 사용자별 지표를 계산한 다음 평균하는 방식(macro-average)을 고려한다.
6. **평가 가능 사용자 수:** 시험 구간에 선호 영화가 하나도 없는 사용자에게 Recall@K의 분모가 0이 되는 문제에 대한 제외·정의 정책을 명시한다.
7. **아이템 수 조건:** 특정 영화의 학습 평점 수가 적어 제외한다면 기준값, 적용 시점(분할 전·후), 시험 대상 변화까지 보고한다. 시험 데이터의 평점 정보를 이용해 필터링 기준을 학습하면 누수가 될 수 있다.

### 7.7 정확도 밖의 추천 품질

- **Coverage:** 전체 영화 중 추천 결과에 등장할 수 있는 영화의 비율.
- **Diversity:** 추천 목록 내 영화들의 장르·특성 다양성.
- **Novelty:** 사용자가 이미 잘 아는 인기 영화만 추천하지 않는 정도.
- **Popularity Bias:** 인기 영화가 추천 결과에 과도하게 집중되는 현상.
- **Cold Start:** 새로운 사용자·영화에 대한 추천 성능 문제.

정확도 한 가지가 높더라도 추천 목록이 매번 비슷한 유명 영화로만 구성된다면 사용자 경험은 제한될 수 있다.

## 8. MovieRecLab에 적용할 평가 실험 설계 예시

> **주의:** 이 절은 현재 진행 중인 MovieRecLab에 적용할 수 있는 **권장 실험 설계**다. 저장소의 실제 구현을 검사하여 확정한 내부 평가 방식이라는 의미는 아니다.

### 8.1 평가 목표 고정

- **목표 A:** 기존 사용자의 숨겨진 평점 예측.
- **목표 B:** 기존 사용자의 숨겨진 선호 영화가 Top-10에 얼마나 포함되는지.
- **확장 목표:** 신규 사용자에게 영화 3~5편의 평점을 입력받은 후 추천할 때의 품질.

목표마다 분할 전략과 평가 지표가 달라지므로 **하나의 수치로 모두 평가하지 않는다.**

### 8.2 권장 파이프라인

1. **데이터 확인:** MovieLens의 사용자 ID, 영화 ID, 평점, 타임스탬프와 영화 메타데이터를 확인한다.
2. **평가 단위 결정:** 기존 사용자 평점 예측이면 **사용자별 평점 기록 분할**을 검토한다. 미래 추천 시나리오라면 사용자별 시간순 분할을 검토한다.
3. **Train / Validation / Test 분리:** 사용자마다 충분한 학습·검증·시험 기록을 확보할 수 있는 최소 기준을 미리 정한다.
4. **학습 데이터만으로 모델 구성:** 인기·평균·유사도·행렬분해 등 평가에 필요한 모델을 학습한다.
5. **동일 조건으로 비교:** 추천 후보군, 평가 대상 사용자, 관련성 기준(예: 4점 이상), K값(예: 5·10)을 고정한다.
6. **Validation으로 선택:** 알고리즘, 가중치, 잠재요인 수, 정규화 강도 등 설정을 조정한다.
7. **Test로 최종 평가:** 확정된 모델을 한 번 최종 평가하고 결과표와 실험 설정을 함께 보고한다.
8. **오류 분석:** 성능이 낮은 사용자, 저평가수 영화, 신규 사용자, 인기 편향 사례를 추가로 확인한다.

### 8.3 비교할 모델 예시

| 모델 | 주요 아이디어 | 학습/설정 포인트 | 권장 평가 |
|---|---|---|---|
| 인기 기반 | 많이 평가되거나 선호된 영화 추천 | 최소 평점 수, 평점 평균과 빈도 결합 | Recall@10, NDCG@10, Coverage |
| 콘텐츠 기반 | 영화 장르·태그·제목 특징으로 유사 영화 추천 | TF-IDF, 사용자 선호 벡터, 코사인 유사도 | Recall@10, NDCG@10, Diversity |
| 협업 필터링 | 비슷한 사용자·영화의 평점 패턴 활용 | 유사도, 이웃 수, 편향 보정 | RMSE, NDCG@10 |
| 행렬분해(SVD 등) | 사용자·영화 잠재요인 학습 | 잠재차원, 정규화, 학습 횟수 | RMSE, NDCG@10 |
| 하이브리드 | 둘 이상의 추천 점수 결합 | 점수 스케일 정규화, 결합 가중치 | NDCG@10, Coverage, Diversity |

**하이브리드의 예시:** 정규화된 협업 필터링 점수 `s_CF`와 콘텐츠 기반 점수 `s_CB`를 아래처럼 합칠 수 있다.

$$s_{hybrid}(u,i)=\alpha s_{CF}(u,i)+(1-\alpha)s_{CB}(u,i)$$

- `α`는 **검증 데이터에서 결정**하고 시험 성능을 보면서 반복 수정하지 않는다.
- 두 점수의 스케일이 다르면 단순 가중합으로 비교하기 어려우므로 사전에 정규화 방식을 정한다.

### 8.4 결과표 양식 (실제 실험 결과로 채워야 함)

| 모델 | RMSE ↓ | MAE ↓ | Precision@10 ↑ | Recall@10 ↑ | NDCG@10 ↑ | Coverage ↑ |
|---|---:|---:|---:|---:|---:|---:|
| 인기 기반 | 해당 시 측정 | 해당 시 측정 | — | — | — | — |
| 콘텐츠 기반 | 해당 시 측정 | 해당 시 측정 | — | — | — | — |
| 협업 필터링 | — | — | — | — | — | — |
| 행렬분해 | — | — | — | — | — | — |
| 하이브리드 | 해당 시 측정 | 해당 시 측정 | — | — | — | — |

- `—`는 **미측정**이며 성능이 0이라는 뜻이 아니다.
- 점수뿐 아니라 **평가 사용자 수, 평가 상호작용 수, 후보 영화 수, 추천 K, 데이터 분할 기준, 난수 시드**를 함께 기록한다.
- 모든 모델이 평점 예측값을 출력하지 않는다면 RMSE를 억지로 계산하지 않고 순위 지표로 비교한다.

### 8.5 결과 해석 예시 (가상)

> A 모델의 RMSE는 B 모델보다 작지만, B 모델의 NDCG@10이 더 높다고 가정하자. 이때 A는 **평점 수치를 더 정확히 예측**하고, B는 **사용자가 선호하는 영화를 상위에 배치하는 능력**이 더 뛰어난 것으로 해석할 수 있다. 추천 목록을 제공하는 서비스라면 B가 더 적합할 수 있지만, Coverage나 신규 사용자 성능도 함께 검토해야 한다.

**위 문장은 평가 지표 해석을 위한 가상 예시이며 MovieRecLab의 실제 성능 결과가 아니다.**

## 9. 베이스라인, 재현성, 올바른 비교

### 9.1 베이스라인 (Baseline)

복잡한 모델이 **단순한 기준보다 실질적으로 개선되었는지** 보여 주는 비교 대상이다.

추천 시스템의 예:

- 전체 평균 평점 예측.
- 사용자 평균 평점 예측.
- 아이템 평균 또는 인기순 추천.

### 9.2 하이퍼파라미터 탐색

- **Grid Search:** 지정한 조합을 전부 비교.
- **Random Search:** 설정 공간에서 일부 조합을 무작위로 탐색.
- **Bayesian Optimization:** 이전 실험 결과를 활용해 다음 탐색 지점을 선택.

탐색 점수가 높다고 해서 그 값이 곧 최종 시험 점수는 아니다. 설정 선택에는 Validation을 사용한다.

### 9.3 재현 가능한 실험 기록

실험 결과를 다른 사람이 확인할 수 있도록 최소한 다음을 남긴다.

- 데이터셋 이름·버전과 전처리·제외 조건.
- 분할 단위·분할 비율·난수 시드.
- 모델 이름과 하이퍼파라미터.
- 학습 데이터 규모와 평가 사용자·아이템 수.
- 성능 지표의 정확한 정의, 관련성 임계값, K값, 후보군.
- 평균뿐 아니라 가능하면 분할 또는 사용자별 편차.

### 9.4 좋은 비교 실험의 조건

**동일한 데이터 분할 + 동일한 평가 대상 + 동일한 후보군 + 동일한 지표**를 최대한 유지해야 알고리즘 자체의 영향을 비교할 수 있다.

서로 다른 시험 집합에서 계산한 NDCG@10을 나란히 놓고 모델의 우열을 단정해서는 안 된다.

| 과적합 | 학습 성능은 높지만 새로운 데이터 성능이 낮은 현상 |
| 데이터 누수 | 예측 시점에 없는 정보가 학습·평가에 유입되는 문제 |
| RMSE / MAE | 평점 등 숫자 예측의 오차를 평가하는 지표 |
| Precision / Recall / F1 | 분류 성능에서 정확히 맞힌 비율과 놓치지 않은 비율 등을 측정 |
| Silhouette | 군집 내부 응집도와 군집 간 분리를 함께 평가 |
| Precision@K / Recall@K | 상위 K개 추천의 정확도와 관련 항목 회수율 |
| NDCG@K | 상위 순위에 관련성 높은 항목이 배치됐는지 평가 |
| Coverage / Diversity | 추천 대상의 폭과 추천 결과의 다양성을 평가 |

## 11. 5분 발표용 핵심 흐름

**1분 — 학습과 평가의 차이**  
“모델 학습은 데이터의 패턴을 이용해 예측 규칙을 만드는 과정이고, 성능 평가는 학습에 사용하지 않은 데이터에서도 좋은 결과를 내는지 확인하는 과정입니다.”

**1분 — 데이터 분할과 과적합**  
“학습·검증·시험 데이터를 구분해야 합니다. 검증 데이터로 설정을 비교하고, 시험 데이터는 최종 평가에 사용합니다. 학습 성능만 높고 시험 성능이 낮다면 과적합을 의심해야 합니다.”

**1분 — 평가지표**  
“회귀는 MAE·RMSE, 분류는 Precision·Recall·F1, 군집화는 Silhouette 같은 지표를 사용합니다. 지표 선택은 문제의 목적에 따라 달라집니다.”

**1분 — 추천 시스템의 특수성**  
“추천 시스템은 평점 예측의 RMSE만으로 평가하기 어렵습니다. 상위 추천에 실제 선호 영화가 들어가는지 보려면 Recall@K, NDCG@K 같은 순위 평가도 필요합니다.”

**1분 — MovieRecLab 연결**  
“우리 프로젝트에서는 데이터 분할과 관련성 기준을 고정하고 여러 추천 알고리즘의 성능을 비교할 수 있습니다. 단순한 인기 기반 모델을 베이스라인으로 두고, 예측 정확도뿐 아니라 순위 품질·다양성도 함께 살펴보는 것이 다음 실험 방향입니다.”

## 12. 확인 문제

1. 학습 데이터로만 평가하면 왜 실제 성능보다 높게 나타날 수 있는가?
2. Train, Validation, Test의 역할은 각각 무엇인가?
3. 파라미터와 하이퍼파라미터의 차이는 무엇인가?
4. 과적합과 과소적합은 학습·검증 손실에서 어떻게 구분되는가?
5. 모델을 선택하면서 Test 점수를 계속 확인하면 어떤 문제가 생기는가?
6. RMSE와 MAE는 어떤 차이가 있는가?
7. Silhouette Score에 정답 레이블이 꼭 필요한가?
8. Precision@5=0.6이면 어떤 뜻인가?
9. RMSE가 더 낮은 모델이 추천 서비스에서 항상 더 좋은 모델인가?
10. “사용자 20% 분리”와 “사용자별 평점 20% 분리”는 어떻게 다른가?

### 간단 정답

1. 이미 본 사례를 기억하여 새로운 데이터에 대한 성능을 과대평가할 수 있기 때문이다.
2. 학습 / 모델·설정 선택 / 최종 일반화 성능 평가.
3. 파라미터는 데이터에서 학습되는 값, 하이퍼파라미터는 학습 전에 설정하거나 검증으로 선택하는 값.
4. 과적합은 Train만 좋고 Validation이 악화; 과소적합은 둘 다 성능이 낮은 경우가 흔하다.
5. 시험 데이터를 모델 선택에 이용한 **평가 누수**가 발생한다.
6. MAE는 절대오차 평균, RMSE는 제곱오차 평균의 제곱근이며 큰 오차에 더 민감하다.
7. 필요 없다. Silhouette는 군집 구조를 내부 거리로 평가한다.
8. 상위 5개 추천 중 3개가 실제 선호 항목이라는 뜻이다(이진 관련성 기준).
9. 아니다. 추천 순위 품질은 NDCG@K·Recall@K 등으로 별도 평가해야 한다.
10. 전자는 사용자를 분리해 신규 사용자 일반화와 관련되고, 후자는 같은 사용자의 일부 평점을 숨겨 기존 사용자 예측과 관련된다.
