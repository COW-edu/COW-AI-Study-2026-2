# COW AI팀 7주차 이론 정리

> **주제:** 머신러닝·딥러닝 모델의 성능 향상 방법 (Performance Optimization)  
> **트랙:** 데이터 사이언스  
> **일정:** 2026년 11월 18일  
> **핵심 질문:** 기존 모델의 성능은 어떤 방법으로, 어떻게 신뢰성 있게 개선할 수 있는가?

## 0. 학습 목표

6주차에 모델을 학습하고 평가하는 방법을 살펴봤다면, 7주차에는 **문제 진단 → 개선 가설 → 통제된 실험 → 재평가**를 반복하는 방법을 다룬다. 모델을 복잡하게 만드는 것 자체가 목적이 아니다. 실제로 원하는 지표를 높이고, 처음 보는 데이터에서도 개선 효과가 유지되도록 만드는 것이 목적이다.

**기본 흐름:** 베이스라인 설정 → 오류·한계 분석 → 데이터/특성/모델/학습 개선 → 동일 조건 비교 → 최종 선택

---

## 1. 무엇을 개선할 것인가?

성능은 여러 측면으로 구성된다.

| 성능의 측면 | 대표 지표 | 의미 |
|---|---|---|
| 예측 품질 | Accuracy, F1, MAE, RMSE | 예측이 정답에 얼마나 가까운가? |
| 순위 품질 | NDCG@K, Recall@K, Hit Rate@K | 중요한 항목을 추천 상위에 배치했는가? |
| 일반화 | 검증·테스트 성능 및 차이 | 처음 보는 데이터에서도 성능이 유지되는가? |
| 추천의 폭 | Coverage, Diversity, Novelty | 다양한 영화와 취향을 반영하는가? |
| 효율성 | 학습 시간, 추론 지연, 메모리 | 실제 서비스에서 감당할 수 있는가? |

평가 지표는 **문제의 목적**과 일치해야 한다. 예컨대 영화 추천에서 Top 10 추천의 품질이 목표라면 평점 예측 RMSE만 낮추는 것으로 충분하지 않다. 또한 후보군과 데이터 분할 방식이 서로 다르면 NDCG 값만으로 모델을 직접 비교하기 어렵다.

## 2. 성능 저하 원인 진단: 편향과 분산

### 2.1 과소적합(Underfitting)

모델이 학습 데이터의 패턴조차 충분히 포착하지 못하는 상태다. 보통 학습 성능과 검증 성능이 모두 낮다.

- 원인: 지나치게 단순한 모델, 정보가 부족한 특성, 과도한 정규화, 충분하지 않은 학습
- 대응: 유용한 특성 추가, 적합한 모델 계열 선택, 정규화 강도 조정, 학습 조건 개선

### 2.2 과적합(Overfitting)

학습 데이터의 우연한 특징이나 잡음까지 외워서 새로운 데이터에서 성능이 떨어지는 상태다. 학습 점수는 높은데 검증 점수가 낮을 수 있다.

- 원인: 높은 모델 복잡도, 데이터 부족, 잡음, 반복적인 검증셋 최적화
- 대응: L1·L2 정규화, 학습 데이터 개선, 교차검증, 조기 종료(Early Stopping), 모델 단순화

### 2.3 학습 곡선으로 진단

| 학습 데이터 성능 | 검증 데이터 성능 | 유력한 문제 | 권장 방향 |
|---|---|---|---|
| 낮음 | 낮음 | 과소적합 가능성 | 표현력·특성·학습량 점검 |
| 높음 | 낮음 | 과적합 가능성 | 정규화·데이터·검증 설계 점검 |
| 높음 | 높음 | 양호 | 추론 비용과 추가 개선 여지 검토 |
| 불안정 | 불안정 | 데이터/학습 분산 | 여러 시드·데이터 분할로 재검증 |

**주의:** 성능의 높고 낮음은 문제와 지표에 따라 달라진다. 표는 진단을 위한 일반적 경향이며 단독으로 원인을 확정하지 않는다.

## 3. 데이터 개선 (Data-Centric AI)

같은 모델이라도 입력 데이터의 품질과 구성에 따라 결과가 크게 달라질 수 있다.

### 3.1 데이터 품질 개선

- **결측치:** 삭제·대체·결측 자체를 특성으로 표현. 결측 발생 원인을 먼저 확인한다.
- **이상치:** 오류 데이터와 실제로 드문 사례를 구분해 처리한다.
- **중복:** 동일한 사례의 중복이나 학습/평가 집합 간 중복을 제거한다.
- **노이즈·라벨 오류:** 잘못된 정답과 일관되지 않은 평가 기준을 수정한다.
- **분포 불균형:** 필요한 경우 가중치 조절, 리샘플링, 세그먼트별 성능 확인을 수행한다.

### 3.2 데이터 양과 다양성

데이터가 증가하면 희귀한 패턴을 더 잘 학습할 수 있지만 **규모 확대만으로 성능 향상이 보장되지는 않는다**. 관련성이 낮은 데이터와 오래된 상호작용은 오히려 목표와 어긋날 수 있다.

영화 추천에서는 유저-영화 상호작용이 희소하므로, 평점 수뿐 아니라 사용자별 평가 수, 영화별 평가 수, 최신성, 장르별 분포도 함께 확인한다.

### 3.3 특성 공학 (Feature Engineering)

원시 데이터를 모델이 학습하기 좋은 형태로 변환하거나 유용한 표현을 추가한다.

- **인코딩:** 범주형 데이터를 원-핫 인코딩 등으로 변환
- **정규화·표준화:** 특징의 크기 차이가 학습에 미치는 영향 조절
- **특성 선택:** 불필요하거나 잡음이 많은 특성 제거
- **특성 결합:** 여러 특성을 조합해 새로운 신호 생성
- **텍스트 표현:** TF-IDF, 임베딩 등으로 제목·장르·태그를 수치화

MovieRecLab에서는 **MovieLens 평점 상호작용 + Tag Genome + 장르/태그/제목 정보**가 각각 서로 다른 선호 신호가 될 수 있다. 어떤 조합이 유효한지는 검증 실험으로 확인해야 한다.

> **데이터 누수 방지:** 스케일러·인코더·벡터라이저·특성 선택기의 통계량을 전체 데이터에서 먼저 학습하고 분할하면 미래의 정보가 모델에 유입될 수 있다. 분할 후 학습셋에서만 `fit`하고, 검증·테스트셋에는 동일한 변환을 적용한다. 추천시스템에서도 시간순 분할을 했다면 평가 시점 이후 상호작용·집계 정보가 특성에 포함되지 않았는지 확인해야 한다.

## 4. 하이퍼파라미터 최적화 (Hyperparameter Tuning)

**모델 파라미터**는 학습 과정에서 데이터로부터 추정되는 값이다. **하이퍼파라미터**는 학습 전에 지정하는 모델·학습의 설정값이다.

| 모델/방식 | 하이퍼파라미터 예시 | 역할 |
|---|---|---|
| K-Means | 군집 수 `k` | 군집의 개수 결정 |
| KNN/ItemKNN | 이웃 수, 유사도, 정규화 | 가까운 이웃의 영향 조절 |
| EASE/Ridge | L2 정규화 강도 `λ` | 계수 크기와 과적합 제어 |
| 행렬분해 | 잠재차원 수, 정규화, 학습률 | 표현력과 일반화 조절 |
| 신경망 | 학습률, 배치 크기, 층·차원 수 | 최적화 경로 및 표현력 조절 |
| 하이브리드 | 모델별 혼합 가중치 | 신호별 기여도 조절 |

### 탐색 방법

- **Grid Search:** 지정된 모든 조합을 탐색. 범위가 커지면 비용 급증.
- **Random Search:** 임의의 조합을 일정 횟수 평가. 제한된 예산에서 효율적일 수 있음.
- **Bayesian Optimization:** 이전 실험 결과를 활용해 유망한 다음 조합을 탐색.
- **Successive Halving/Hyperband:** 성능이 떨어지는 후보의 자원 투입을 조기에 중단.

**올바른 절차:** 훈련셋에서 모델 학습 → 검증셋에서 하이퍼파라미터 선택 → 테스트셋에서 최종 성능을 한 번 평가. 테스트 결과를 보고 계속 설정을 바꾸면 테스트셋도 사실상 튜닝에 사용한 셈이 된다.

### 예시: EASE

정규화가 있는 선형 모델의 대표적인 목적함수 형태는 다음과 같다.

\[
\min_B \; \|X-XB\|_F^2 + \lambda \|B\|_F^2, \quad \operatorname{diag}(B)=0
\]

- `X`: 사용자-아이템 상호작용 행렬
- `B`: 아이템 간 선형 관계를 나타내는 가중치 행렬
- `λ`: 정규화 강도
- `diag(B)=0`: 아이템 자신에 대한 가중치 제거

일반적으로 `λ`를 늘리면 가중치의 크기가 더 강하게 제한된다. 다만 최적 `λ`는 데이터에 따라 다르므로 검증셋에서 선택한다.

## 5. 학습 과정 최적화

### 5.1 정규화 (Regularization)

복잡한 모델이 학습 데이터에 과도하게 적합되는 것을 완화한다.

- **L1 정규화:** 가중치 절댓값의 합에 패널티. 일부 가중치를 0으로 만드는 경향.
- **L2 정규화:** 가중치 제곱합에 패널티. 큰 가중치를 부드럽게 제한.
- **Dropout:** 학습 중 신경망의 일부 연결을 확률적으로 비활성화해 과도한 의존성을 감소.
- **Weight Decay:** 옵티마이저에서 가중치가 과도하게 커지는 것을 억제. 구현 방식에 따라 L2 페널티와 정확한 동작이 다를 수 있음.

### 5.2 조기 종료 (Early Stopping)

학습 손실이 계속 감소해도 검증 성능이 악화되기 시작하면 학습을 멈추고 좋은 체크포인트를 선택한다.

### 5.3 학습률 (Learning Rate)

- 너무 큼: 최적값 주변에서 진동하거나 발산할 수 있음.
- 너무 작음: 학습이 느리거나 불충분해질 수 있음.
- **Learning Rate Scheduler:** 학습 진행에 따라 학습률을 조정.

### 5.4 배치 크기·옵티마이저

배치 크기는 메모리·연산 효율·그라디언트 잡음에 영향을 준다. SGD, Momentum, Adam, AdamW 등 옵티마이저마다 수렴 특성이 다르다. 특정 방식이 모든 데이터에서 최고인 것은 아니다.

### 5.5 전이 학습·데이터 증강

이미 학습된 모델을 새 문제에 맞게 미세조정하거나, 라벨의 의미를 보존하는 변형으로 학습 데이터를 확장한다. 이미지·텍스트에서 유용하지만, 영화 평점 행렬을 임의로 바꾸는 방식은 실제 선호 관계를 훼손할 수 있으므로 주의한다.

## 6. 모델 개선·앙상블·하이브리드

### 6.1 알고리즘 변경

문제 특성에 따라 모델의 귀납적 편향이 다르다. 예컨대 같은 추천 문제도 인기 기반, 사용자 협업필터링, 아이템 협업필터링, 행렬분해, 콘텐츠 기반 방법이 포착하는 신호가 다르다. **더 복잡한 모델이 언제나 우수한 것은 아니다.**

### 6.2 앙상블 (Ensemble)

서로 다른 모델의 예측을 결합해 단일 모델의 약점을 보완한다.

- **Bagging:** 서로 다른 표본으로 학습한 모델들의 출력을 통합해 분산 감소를 노린다.
- **Boosting:** 이전 모델이 잘 처리하지 못한 부분을 후속 모델이 보완한다.
- **Stacking:** 여러 모델의 예측을 또 다른 메타 모델의 입력으로 사용한다.
- **Blending/Hybrid:** 여러 점수 또는 순위를 가중 결합한다.

### 6.3 하이브리드 추천 점수

예를 들어 서로 보정된 점수라면 다음처럼 결합할 수 있다.

\[
s(u,i)=\alpha s_{EASE}(u,i)+\beta s_{ItemKNN}(u,i)+\gamma s_{Content}(u,i)
\]

여기서 `u`는 사용자, `i`는 영화, `α·β·γ`는 혼합 가중치다. 가중치의 합을 1로 정할 수 있으나 반드시 그래야 하는 것은 아니다. **서로 다른 모델의 원점수 스케일이 다르면 결합 전에 정규화·보정해야 한다.** 가중치는 검증셋에서 조정하며, 단일 모델보다 낮아질 가능성도 고려한다.

### 6.4 Ablation Study (절제 실험)

전체 모델에서 요소를 하나씩 제거해 실제 기여도를 분석한다.

| 실험 | 비교 질문 |
|---|---|
| EASE 단독 | 기본 협업 신호의 성능은? |
| EASE + ItemKNN | 아이템 유사도가 추가 가치를 주는가? |
| EASE + 콘텐츠 | 장르·태그 신호가 도움이 되는가? |
| 전체 혼합 | 여러 신호의 결합이 개별 모델보다 좋은가? |

위 표는 **실험 설계 예시**이며 실제 결과가 아니다.

## 7. 추천 시스템의 성능 향상: MovieRecLab 사례

영화 추천의 목표는 평점 자체를 정확히 맞히는 것뿐 아니라 **상위 K개 추천의 순서와 사용자의 만족도**를 개선하는 것이다.

### 7.1 3단계 추천 파이프라인

1. **후보 생성(Candidate Generation):** EASE, ItemKNN, 콘텐츠 기반 등으로 유망한 영화 후보를 수집한다.
2. **점수 계산·정렬(Scoring/Ranking):** 후보별 개인화 점수를 계산하고 상위 영화를 선정한다.
3. **재정렬(Re-ranking):** 장르 다양성, 반복 추천 방지, 이미 평가한 영화 제외, 신작/롱테일 노출 등 추가 기준을 반영한다.

후보 생성 단계에서 누락된 영화를 후속 랭커가 복구할 수 없기 때문에 **후보 집합의 Recall**도 중요하다. 재정렬은 다양성을 높일 수 있지만 정확도와의 균형이 필요하다.

### 7.2 추천 평가 지표

> `K`는 추천 목록 상위 K개의 길이. 평가에서 '정답 영화'를 어떻게 정의하는지(예: 일정 평점 이상)와 사용자별 정답 수가 핵심이다.

**Precision@K:** 추천한 K개 중 관련 있는 영화의 비율.

\[
Precision@K=\frac{|R_K\cap G|}{K}
\]

**Recall@K:** 평가 대상 관련 영화 중 추천에 포함된 비율.

\[
Recall@K=\frac{|R_K\cap G|}{|G|}
\]

**Hit Rate@K:** 사용자별로 상위 K개에 정답이 1개 이상 있으면 성공으로 보고, 성공한 사용자 비율을 계산. (하나의 정답만 남기는 평가 프로토콜에서는 Recall@K와 같아질 수 있다.)

**NDCG@K:** 관련 있는 영화를 목록 상단에 놓을수록 높은 점수를 주는 순위 지표.

\[
DCG@K=\sum_{j=1}^{K}\frac{2^{rel_j}-1}{\log_2(j+1)},\qquad NDCG@K=\frac{DCG@K}{IDCG@K}
\]

- `rel_j`: j번째 영화의 관련성 점수 (이진 관련성 또는 등급형 관련성)
- `IDCG`: 가장 이상적으로 정렬했을 때의 DCG
- 정답 영화가 첫 번째에 나오면 그 영화의 할인 계수는 `1`, 다섯 번째에 나오면 약 `0.387`이 된다.
- 평가 대상에 관련 영화가 하나도 없는 사용자는 처리 규칙을 명시해야 한다.

**Catalog Coverage@K:** 전체 추천 가능 영화 중 적어도 한 사용자에게 한 번 이상 추천된 영화의 비율. 단, 단순 노출 확대가 개인별 품질 향상을 보장하지는 않는다.

**Diversity:** 한 추천 목록 안에서 장르·임베딩 유사도 등으로 측정한 상이함. **Novelty:** 일반적으로 덜 알려졌거나 덜 소비되는 항목을 제안하는 성격. 모두 정확도와 함께 살펴볼 보조 지표다.

### 7.3 오프라인 평가를 제대로 설계하는 방법

1. **시간순 분할:** 각 사용자에 대해 과거 평점으로 학습하고 미래 평점을 정답으로 두어 실제 서비스 상황을 가깝게 재현한다. 전역 시간순 분할도 가능하며 목적에 맞게 선택한다.
2. **사용자별 최소 이력:** 학습·평가를 위한 상호작용이 부족한 사용자는 별도의 콜드스타트 집단으로 평가하거나 프로토콜을 명시한다.
3. **동일한 후보군:** 모델마다 추천할 수 있는 영화의 범위와 이미 본 영화 제외 규칙을 동일하게 적용한다.
4. **명시적 평점의 관련성 정의:** 4점 이상 등을 관련 영화로 삼을 수 있으나 이는 **설계 예시**이고 정답 기준에 따라 결과가 달라진다.
5. **노출 편향 인식:** 평점이 없는 영화를 사용자가 싫어한다고 단정할 수 없다. 미관측은 반드시 부정 피드백이 아니다.
6. **분리된 검증·테스트:** 조합/하이퍼파라미터는 검증셋에서만 결정한다. 가능하면 여러 분할·시드의 평균과 변동도 확인한다.

### 7.4 프로젝트에 적용 가능한 개선 실험

MovieRecLab은 MovieLens 25M, Tag Genome, EASE·ItemKNN 및 여러 추천 모델, 하이브리드 추천을 실험한 프로젝트다. 다음은 **추가 실험 제안**이며 확정된 성과가 아니다.

| 우선순위 | 변경 요소 | 비교 방법 | 확인 지표 |
|---|---|---|---|
| 1 | 데이터 분할과 후보군 정렬 | 같은 조건으로 기존 모델 재평가 | NDCG@10, Recall@10 |
| 2 | EASE L2 정규화 | 검증셋에서 λ 탐색 | NDCG@10, 속도 |
| 3 | ItemKNN 이웃 수·유사도 | 한 번에 한 요소만 변경 | NDCG@10, Coverage |
| 4 | Tag Genome/콘텐츠 특징 추가 | 콘텐츠 특징 포함/제거 | NDCG@10, 콜드스타트 |
| 5 | 하이브리드 가중치 조절 | 점수 보정 후 가중치 탐색 | NDCG@10, Recall@10 |
| 6 | 재정렬 다양성 조절 | 동일 후보에 다양성 규칙 추가 | NDCG@10, Diversity |
| 7 | 사용자 이력 구간별 분석 | 평가 3~5편, 6~20편, 20편 이상 등 구간 비교 | 구간별 NDCG@10 |

**중요:** 25M에서 어느 모델이 가장 좋은지에 관한 과거 결과를 다른 데이터 분할, 후보 집합, 평가 프로토콜에 그대로 일반화하면 안 된다. 실제 모델 선택은 **동일 조건에서의 최신 실험 결과**를 근거로 해야 한다.

## 8. 성능 개선 실험 설계 원칙

**1. 베이스라인 고정:** 데이터 버전, 분할, 평가 코드, 랜덤 시드, 후보군, 계산 자원을 먼저 기록한다.

**2. 한 번에 한 요소 변경:** 가능한 한 하나의 변수만 수정해 인과적인 해석을 쉽게 한다. 이후 조합 실험을 진행한다.

**3. 다중 지표 기록:** 주지표(예: NDCG@10)와 보조지표(Recall, Coverage, 지연 시간)를 나누어 기록한다.

**4. 반복성과 불확실성:** 복수의 시드·분할을 사용하고, 가능하면 사용자 단위 부트스트랩 신뢰구간으로 차이가 우연인지 점검한다. 단 한 번의 점수 상승이 유의한 개선을 뜻하지는 않는다.

**5. 통계적 유의성과 실용성 구분:** 차이가 통계적으로 유의해도 실제 사용자에게 무의미할 수 있으며, 역도 가능하다. 모델 크기와 운영 비용을 함께 고려한다.

**6. 롤백 가능한 개선:** 설정과 실험 결과를 버전 관리한다. 검증되지 않은 모델을 기존 서비스에 즉시 덮어씌우지 않는다.

## 9. 자주 발생하는 실수

- **테스트셋 튜닝:** 테스트 점수를 보며 파라미터를 계속 바꾼다 → 데이터 누수의 한 형태가 된다.
- **지표 혼동:** RMSE가 낮다고 Top-K 추천이 무조건 좋다고 해석한다.
- **불공정한 비교:** 비교 모델의 데이터·후보군·평가 정의가 다르다.
- **데이터 규모 맹신:** 데이터셋만 키우면 반드시 성능이 오른다고 생각한다.
- **하이브리드 만능론:** 모델을 여러 개 섞으면 무조건 좋아진다고 기대한다.
- **결과 선별:** 좋은 시드·좋은 분할 결과만 보고한다.
- **서비스 성능 무시:** 오프라인 점수만 높고 추천 계산 시간이 과도하다.

### 예상 질문과 답변

**Q. 더 복잡한 모델로 바꾸면 무조건 성능이 올라가나요?**  
A. 아니다. 데이터의 규모·노이즈·희소성에 따라 단순 모델이 더 잘 일반화할 수 있다.

**Q. Grid Search와 Random Search의 차이는?**  
A. Grid Search는 지정한 조합 전체를, Random Search는 지정된 분포에서 샘플링한 조합을 평가한다. 예산이 제한될 때 Random Search가 유리할 수 있다.

**Q. NDCG가 높다는 것은 무엇을 뜻하나요?**  
A. 정의된 정답·관련성 기준에 따라 중요한 영화를 추천 목록 상위에 더 잘 배치했다는 뜻이다.

**Q. 하이브리드가 EASE 단독보다 항상 좋나요?**  
A. 아니다. 점수 보정·혼합 가중치·데이터 특성에 따라 성능이 악화할 수 있다.

**Q. 6주차의 모델 평가와 7주차의 성능 향상은 무엇이 다른가요?**  
A. 6주차는 모델을 학습하고 현 수준을 측정하는 방법, 7주차는 그 결과를 진단해 개선 가설을 세우고 공정한 실험으로 검증하는 방법에 초점을 둔다.

## 11. 핵심 요약

> **좋은 성능 개선은 ‘복잡한 모델을 도입하는 것’이 아니라, 어떤 원인 때문에 성능이 낮은지 파악하고, 변경 사항의 효과를 동일한 평가 환경에서 검증하는 과정이다.**

- **데이터 개선:** 결측·노이즈·중복 처리, 정보량이 높은 특성 추가
- **학습 개선:** 하이퍼파라미터 튜닝, 정규화, Early Stopping
- **모델 개선:** 적절한 알고리즘 선택, 하이브리드·앙상블
- **추천 특화:** 후보 생성·순위화·재정렬, NDCG@K와 Recall@K 평가
- **신뢰성 확보:** 누수 방지, 테스트셋 독립성, 동일 조건 비교, 반복 검증
