# 데이터 전처리(Data Preprocessing) 이론

> COW AI팀 스터디 자료  
> 주제: 데이터 전처리의 목적, 주요 기법, 적용 시 주의사항  
> 적용 예시: Shopping Behavior and Preferences 데이터셋

## 1. 데이터 전처리란?

데이터 전처리(Data Preprocessing)는 수집한 원본 데이터를 분석 및 머신러닝에 적합한 형태로 정리하고 변환하는 과정이다. 원본 데이터에는 누락된 값, 입력 오류, 중복, 이상치, 서로 다른 자료형과 단위 등이 포함될 수 있다.

전처리의 목적은 단순히 데이터를 '깨끗하게' 만드는 것이 아니라 **분석 목적에 적합한 정보를 보존하면서 데이터의 품질과 모델의 신뢰성을 높이는 것**이다. 따라서 모든 데이터에 동일한 전처리 규칙을 적용하는 것은 적절하지 않다.

일반적인 분석 흐름은 다음과 같다.

1. 분석 목적 및 문제 정의
2. 데이터 수집과 구조 파악
3. 탐색적 데이터 분석(EDA)
4. 데이터 정제 및 변환
5. 변수 선택과 특징 생성
6. 모델 학습 및 평가

전처리와 EDA는 일회성 선형 과정이 아니다. 탐색 중 문제가 발견되면 전처리 방법을 수정하고 다시 확인하는 과정을 반복한다.

## 2. 데이터의 구조와 자료형 이해

### 2.1 관측치와 변수

- **관측치(Observation)**: 표 형태의 데이터에서 보통 한 행(row)에 해당한다. 예를 들어 한 고객의 구매 기록이다.
- **변수(Variable 또는 Feature)**: 각 관측치의 특성을 나타내며 보통 한 열(column)에 해당한다. 예: 나이, 구매 금액, 상품 카테고리.
- **목표변수(Target)**: 지도학습에서 예측하려는 변수이다. 군집화처럼 정답 레이블이 없는 비지도학습에는 목표변수가 없을 수 있다.

### 2.2 수치형과 범주형

| 구분 | 설명 | 예시 | 대표적인 전처리 |
| --- | --- | --- | --- |
| 연속형 수치 | 일정 범위에서 여러 실수값을 가짐 | 구매 금액, 평점 | 결측치 대체, 스케일링 |
| 이산형 수치 | 셀 수 있는 값을 가짐 | 이전 구매 횟수 | 결측치 대체, 분포 확인 |
| 명목형 범주 | 범주 사이에 순서가 없음 | 성별, 상품 종류, 결제 방식 | 원-핫 인코딩 등 |
| 순서형 범주 | 범주 사이에 순서가 있음 | 만족도 단계, 순위 | 순서 인코딩 등 |
| 식별자 | 행이나 대상을 구분하는 값 | 고객 ID | 대개 학습 변수에서 제외 |

**주의:** 숫자로 표현되어 있다고 해서 반드시 수치형 특징인 것은 아니다. 고객 ID나 우편번호는 숫자처럼 보여도 크기 차이에 의미가 없는 경우가 많다.

## 3. 데이터 탐색(EDA)과 품질 점검

전처리 전에 다음을 확인하는 것이 좋다.

- 행과 열의 개수, 열 이름, 자료형
- 결측치의 개수와 비율
- 중복된 행과 식별자의 중복 여부
- 수치형 변수의 평균, 중앙값, 최솟값, 최댓값, 표준편차
- 범주형 변수의 고유값과 빈도
- 특정 값에 지나치게 집중되어 있는지 여부
- 변수 간 관계, 이상한 조합, 논리적으로 불가능한 값

대표적인 EDA 시각화에는 히스토그램, 막대그래프, 박스플롯, 산점도, 상관계수 히트맵 등이 있다. 상관계수는 관계를 이해하는 참고 지표일 뿐 인과관계를 증명하지 않는다.

## 4. 결측치(Missing Value) 처리

결측치는 실제 값이 기록되지 않은 상태를 말한다. 단순히 빈 칸일 수도 있고 `NaN`, `None`, `NULL`, `Unknown`, `-1` 등의 형태로 표현될 수도 있다. 다만 `Unknown`이나 `-1`을 무조건 결측치로 간주해서는 안 되며 데이터 정의를 먼저 확인해야 한다.

### 4.1 결측치가 발생하는 이유

- 응답자가 설문에 답하지 않음
- 센서나 시스템의 기록 실패
- 데이터 수집 또는 병합 과정의 오류
- 특정 대상에게 해당 사항이 없음

### 4.2 주요 처리 방법

| 방법 | 설명 | 고려사항 |
| --- | --- | --- |
| 행 삭제 | 결측치가 포함된 관측치를 삭제 | 표본 수 감소 및 편향 가능 |
| 열 삭제 | 결측치가 많거나 활용 가치가 낮은 변수를 제외 | 중요한 정보 손실 가능 |
| 평균 대체 | 수치형 결측치를 평균으로 대체 | 이상치에 민감, 분산 감소 가능 |
| 중앙값 대체 | 수치형 결측치를 중앙값으로 대체 | 치우친 분포와 이상치에 비교적 강건 |
| 최빈값 대체 | 가장 빈번한 값으로 대체 | 범주 분포를 왜곡할 수 있음 |
| 별도 범주 | 범주형 결측치를 `Missing` 등으로 표시 | 결측 자체에 의미가 있을 때 유용 |
| 예측 기반 대체 | 다른 변수로 결측치를 예측 | 복잡성 및 과적합 주의 |

**핵심:** 결측치 발생 방식에 따라 적절한 처리법이 달라진다. 또한 결측 자체가 의미 있는 신호일 수 있어 결측 여부를 별도 변수로 추가하기도 한다.

## 5. 중복 데이터(Duplicate) 처리

중복은 동일한 기록이 여러 번 저장되었거나 서로 다른 행이 실제로 같은 사건을 가리키는 문제이다.

- **완전 중복:** 모든 열의 값이 동일한 행이 반복됨
- **부분 중복:** 일부 열이나 식별자가 같지만 나머지 정보는 다름

중복을 삭제하기 전에 **한 행이 무엇을 의미하는지** 정의해야 한다. 예를 들어 동일 고객이 여러 번 구매했다면 고객 ID가 같더라도 정상적인 구매 기록일 수 있다. 반대로 설문에서 응답자당 한 행만 존재해야 한다면 고객 ID 중복은 점검 대상이다.

## 6. 이상치(Outlier) 처리

이상치는 다른 관측치에 비해 매우 크거나 작은 값, 또는 일반적인 패턴에서 벗어난 값을 뜻한다. 모든 이상치가 오류인 것은 아니다. 예를 들어 구매 금액이 매우 높은 고객은 실제 고액 구매자일 수 있다.

### 6.1 IQR 방식

사분위수 범위(Interquartile Range)는 다음과 같다.

\[
IQR = Q_3 - Q_1
\]

관례적으로 아래 구간을 벗어나는 관측치를 이상치 **후보**로 표시한다.

\[
x < Q_1 - 1.5\,IQR \quad \text{또는} \quad x > Q_3 + 1.5\,IQR
\]

이 기준은 탐지용 경험칙이지 삭제해야 하는 절대적인 규칙이 아니다.

### 6.2 Z-score 방식

\[
z = \frac{x-\mu}{\sigma}
\]

관례적으로 `|z| > 3`을 극단값 탐지 기준으로 사용할 수 있다. 하지만 분포가 심하게 치우쳤거나 이상치가 많으면 평균과 표준편차 자체가 영향을 받는다.

### 6.3 처리 선택지

1. 단위·입력 오류가 확인되면 수정하거나 제외한다.
2. 실제 발생한 드문 사례라면 보존을 우선 검토한다.
3. 모델이 극단값에 민감하면 로그 변환, 강건 스케일링, 상·하한 제한 등을 고려한다.
4. 처리 전후 결과를 비교해 중요한 정보를 잃지 않았는지 확인한다.

## 7. 범주형 데이터 인코딩(Encoding)

많은 머신러닝 알고리즘은 문자열을 직접 입력받지 못하므로 범주형 변수를 수치 형태로 변환해야 한다.

### 7.1 레이블/순서 인코딩

예를 들어 작은 크기, 중간 크기, 큰 크기에 각각 `0`, `1`, `2`를 부여할 수 있다. 크기처럼 **실제로 순서가 존재하는 변수**에 적절하다. 반면 결제 방식처럼 순서가 없는 변수에 임의의 번호를 부여하면 알고리즘이 잘못된 크기·거리 관계를 해석할 수 있다.

### 7.2 원-핫 인코딩(One-Hot Encoding)

범주마다 별도의 이진 변수를 만든다.

| 원래 값 | Red | Blue | Green |
| --- | ---: | ---: | ---: |
| Red | 1 | 0 | 0 |
| Blue | 0 | 1 | 0 |
| Green | 0 | 0 | 1 |

순서가 없는 범주에 주로 적합하다. 다만 범주 수가 매우 많으면 차원이 크게 증가하고 희소한 표현이 만들어질 수 있다.

### 7.3 기타 인코딩

- **빈도 인코딩:** 범주의 출현 횟수 또는 비율을 사용한다.
- **타깃 인코딩:** 범주별 타깃 통계량을 사용한다. 데이터 누출과 과적합에 특히 주의해야 하며 교차검증 기반 방법이 권장된다.

어떤 인코딩이 좋은지는 모델, 범주 수, 변수의 의미와 분석 목적에 따라 달라진다.

## 8. 수치형 데이터 스케일링(Scaling)

스케일링은 수치형 변수의 값 범위나 분포 특성을 조정하는 작업이다. 특히 **거리 기반 알고리즘**에서는 변수의 단위와 크기가 결과를 크게 바꿀 수 있다.

예를 들어 나이는 20~60 사이지만 구매 금액은 수백 또는 수천 단위라면, 별도 조정 없이 유클리드 거리를 사용할 경우 구매 금액이 거리 계산에 더 큰 영향을 미칠 수 있다.

### 8.1 표준화(Standardization)

\[
z = \frac{x-\mu}{\sigma}
\]

각 변수에서 평균을 빼고 표준편차로 나눈다. 학습 데이터 기준으로 평균이 0, 분산이 1이 되도록 변환하는 방식이다. 일반적인 표준화가 정규분포를 만들어 주는 것은 아니다.

### 8.2 최소-최대 정규화(Min-Max Scaling)

\[
x' = \frac{x-x_{\min}}{x_{\max}-x_{\min}}
\]

학습 데이터의 최솟값과 최댓값을 이용하여 보통 0~1 범위로 조정한다. 새로운 데이터가 학습 범위를 벗어나면 변환값이 0보다 작거나 1보다 커질 수도 있다. 이상치에도 민감하다.

### 8.3 강건 스케일링(Robust Scaling)

\[
x' = \frac{x-\operatorname{median}(x)}{IQR(x)}
\]

중앙값과 IQR을 사용해 이상치의 영향을 상대적으로 줄인다.

### 8.4 어떤 방법을 선택할까?

- 거리 기반 모델(K-Means, KNN 등): 변수별 규모를 확인하고 스케일링을 적극 검토한다.
- 선형 모델, 신경망: 스케일링이 학습 안정성과 최적화에 도움이 되는 경우가 많다.
- 의사결정나무 및 일반적인 트리 앙상블: 스케일링의 필요성이 상대적으로 낮다.
- 심한 이상치가 있는 변수: RobustScaler, 로그 변환 등을 검토한다.

**용어 주의:** 실무에서 정규화(normalization)는 문맥에 따라 Min-Max 변환이나 벡터의 길이를 1로 맞추는 정규화를 가리키기도 한다. 자료에서 사용하는 뜻을 명시해야 한다.

## 9. 특징 선택(Feature Selection)과 특징 생성(Feature Engineering)

### 9.1 특징 선택

분석 목적과 관련성이 낮거나 불필요한 변수를 제외하는 과정이다.

- 식별자처럼 예측 의미가 없는 변수
- 정보가 거의 없는 상수형 변수
- 동일한 정보를 과도하게 반복하는 변수
- 정답 또는 미래 정보를 사전에 알려 주는 누출 변수

단, 중복성과 관련성은 모델에 따라 다르게 작용하므로 상관계수가 높다는 이유만으로 무조건 삭제하지 않는다.

### 9.2 특징 생성

기존 변수에서 새로운 의미 있는 변수를 만든다.

- 구매일로부터 계절, 요일 등의 파생 변수 생성
- 금액과 수량으로 단가 계산(적합한 데이터가 있을 때)
- 구매 횟수나 구매 금액으로 고객 행동 지표 구성

파생 변수는 원본에 존재하는 정보만으로 만들어야 하고, 예측 시점에 알 수 없는 정보를 섞지 않도록 한다.

## 10. 데이터 누출(Data Leakage) 방지

데이터 누출은 모델이 실제 예측 시점에 이용할 수 없는 정보를 학습 과정에서 미리 접하는 문제이다. 평가 점수가 비현실적으로 높게 나올 수 있다.

지도학습의 올바른 기본 순서는 다음과 같다.

1. 학습용 데이터와 검증·시험용 데이터를 적절히 분할한다.
2. 평균·중앙값·최솟값·최댓값·인코딩 범주 등 필요한 전처리 기준은 **학습 데이터에 대해서만 학습(fit)** 한다.
3. 학습한 전처리기를 이용하여 검증·시험 데이터를 **변환(transform)** 한다.
4. 모델 및 하이퍼파라미터를 학습·검증한 뒤 최종 시험 데이터로 평가한다.

같은 고객의 여러 기록이 존재하면 고객 기준으로 나누는 그룹 분할이 필요할 수 있고, 시간에 따라 예측하는 문제라면 시간 순서를 지키는 분할이 중요하다. 이러한 경우 단순 무작위 분할은 누출을 일으킬 수 있다.

`Pipeline` 및 `ColumnTransformer`를 활용하면 모델 학습과 전처리의 순서를 일관되게 유지할 수 있다.

## 11. 군집화(Clustering)에서 전처리가 중요한 이유

COW에서 고객 데이터를 군집화할 경우, 특히 K-Means 같은 거리 기반 모델은 전처리의 영향을 많이 받는다.

### 11.1 유클리드 거리

두 데이터 포인트 \(\mathbf{x}, \mathbf{y}\) 간 유클리드 거리는 다음과 같다.

\[
d(\mathbf{x},\mathbf{y}) = \sqrt{\sum_{j=1}^{p}(x_j-y_j)^2}
\]

수치형 변수의 단위 차이, 원-핫 인코딩으로 늘어난 범주형 변수의 수, 이상치가 모두 거리 계산에 영향을 준다.

### 11.2 실무상 주의점

- **K-Means는 범주형과 수치형이 혼합된 데이터를 그대로 처리하기에 항상 적합하지 않다.** 원-핫 인코딩 후 K-Means를 사용할 수 있지만 해석에 주의해야 한다.
- 범주형 변수가 많으면 원-핫 인코딩된 여러 열이 거리에서 큰 비중을 차지할 수 있다.
- 데이터에 따라 K-Prototypes(혼합 자료형), Gower 거리 기반 군집화 등 다른 접근을 검토할 수 있다.
- 군집 개수는 엘보 방법, 실루엣 점수 등을 참고할 수 있지만 수치 하나만으로 최적값을 확정할 수는 없다.
- 군집 분석에서는 군집별 특성을 원본 단위로 다시 해석하는 과정이 중요하다.

### 12.1 분석 목표에 따른 선택

**고객 구매 행동 군집화**를 목표로 한다면 먼저 다음 질문을 검토할 수 있다.

- 고객 간 비교에서 무엇을 중요하게 볼 것인가? 구매 금액, 빈도, 취향, 프로모션 이용 여부 등
- 행 하나가 고객 한 명인지 구매 한 건인지 확인했는가?
- 상품 색상처럼 군집 목표와 관련성이 낮을 수 있는 변수를 포함할 필요가 있는가?
- 한 범주형 변수가 여러 개의 원-핫 열로 나뉘면서 다른 변수보다 지나치게 큰 영향력을 갖게 되지는 않는가?
- 만들어진 군집은 실제 고객 유형을 설명하는가?

### 12.2 전처리 진행 예시

1. CSV 파일을 읽어 행·열 수와 자료형을 확인한다.
2. 결측치, 중복, 이상한 값, 변수별 분포를 조사한다.
3. 군집화 목적에 맞춰 `Customer ID` 등 식별자를 제외한다.
4. 수치형 변수는 분포를 확인하고 필요에 따라 스케일링한다.
5. 범주형 변수는 의미에 따라 원-핫 또는 순서 인코딩한다.
6. 군집화 알고리즘을 적용하고 군집 수 및 품질을 검토한다.
7. 군집별 구매 금액·나이·구매 빈도 등의 분포를 **원래 단위로** 비교해 결과를 해석한다.

> 이 순서는 학습을 위한 예시이다. 실제 데이터의 상태와 군집화 목표에 따라 일부 단계가 변경되거나 생략될 수 있다.

## 13. 자주 발생하는 전처리 실수

1. 평균으로 모든 결측치를 일괄 대체한다.
2. 이상치라는 이유만으로 실제 관측치를 전부 삭제한다.
3. 순서가 없는 범주형 변수에 임의의 정수 번호를 붙인다.
4. 학습·시험 데이터를 나누기 전에 전체 데이터로 스케일러를 학습한다.
5. 고객 ID 같은 식별자를 모델 입력에 포함한다.
6. 분석 목적을 고려하지 않고 모든 변수를 무조건 사용한다.
7. 원-핫 인코딩으로 변수 수가 증가했는데 거리 기여도를 확인하지 않는다.
8. 군집 품질 점수만 비교하고 군집의 실제 의미를 해석하지 않는다.

## 14. 발표 및 토론용 핵심 질문

- 데이터 전처리가 모델의 결과를 바꾸는 이유는 무엇인가?
- 결측치를 삭제할 때와 대체할 때 각각 어떤 문제가 발생할 수 있는가?
- 실제로 존재하는 극단적인 구매 금액은 제거해야 하는가?
- 성별과 결제 수단에 순서 인코딩을 적용하면 무엇이 문제인가?
- 표준화와 최소-최대 정규화의 차이는 무엇인가?
- K-Means에서 스케일링이 중요한 이유는 무엇인가?
- 고객 ID를 분석 변수로 사용하면 어떤 문제가 생기는가?
- 학습 데이터에만 전처리 기준을 맞춰야 하는 이유는 무엇인가?
- 군집별 특성을 해석할 때 어떤 통계량과 시각화를 사용하는 것이 좋은가?

## 15. 요약

데이터 전처리는 **결측치·중복·이상치 처리 → 범주형 인코딩 및 수치형 스케일링 → 특징 선택과 변환 → 모델 적용 및 결과 검증**으로 연결된다. 중요한 것은 정해진 기법을 모두 사용하는 것이 아니라 **데이터의 의미, 분석 목표, 알고리즘의 특성을 고려해 처리 방식을 선택하는 것**이다.

특히 고객 군집화에서는 분석 목적에 맞는 변수 선택, 범주형 자료의 거리 해석, 수치형 변수의 규모 조정이 결과를 좌우한다. 전처리 과정의 근거를 기록하고, 처리 전후 데이터 분포 및 군집 결과를 비교하는 것이 좋다.
